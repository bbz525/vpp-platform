# 产品立项

## 1. 背景

分布式光伏、储能和充电桩通常分散在不同站点、协议和系统中。运营方难以实时掌握可调资源，无法稳定执行峰谷套利、削峰填谷和需求响应，也很难回答“为什么这样调度、是否执行成功、实际节省了多少”这些关键问题。

本项目通过统一设备接入、实时计算、预测、优化调度和审计，将分散资源聚合为可运营的虚拟电厂。

## 2. 核心问题

1. 设备协议和数据质量不一致，状态不可统一观测。
2. 功率、电量和电价曲线量大且持续产生，传统业务数据库难以支撑实时分析。
3. 日前计划依赖负荷与光伏预测，人工排程慢且难以持续修正。
4. 调度涉及安全边界、审批、指令回执和失败补偿，不能只生成一条“最优曲线”。
5. 需求响应和异常处置缺少可追溯证据，收益与责任难以核验。

## 3. 目标用户

| 用户 | 主要任务 | MVP 权限 |
| --- | --- | --- |
| VPP 运营员 | 监控资源、查看预测、生成并审批计划、处置告警 | 读写计划与告警、下发调度 |
| 能源分析师 | 分析负荷、光伏、电价、预测误差和调度收益 | 只读分析、导出 |
| 站点管理员 | 管理本站设备、查看本站执行情况 | 站点范围读写 |
| 系统管理员 | 租户、用户、设备型号、规则和系统参数管理 | 管理权限 |
| 审计员 | 还原调度决策与操作历史 | 全局只读审计 |

## 4. 产品目标

- 统一接入光伏逆变器、储能系统、充电桩和智能电表的模拟遥测。
- 在秒级展示组合、站点和设备状态，并识别离线、越界和数据异常。
- 每日生成次日 96 个 15 分钟时段的负荷与光伏预测。
- 在电价、SOC、功率、容量和设备可用性约束下生成可执行调度计划。
- 支持人工审批、自动下发、回执跟踪、失败重试和紧急停止。
- 支持需求响应事件的容量评估、目标分解、执行和效果核算。
- 为所有配置、预测、优化、审批和执行行为保留不可静默修改的审计记录。

## 5. 非目标

MVP 不包含：

- 真实电网调度机构或电力交易中心认证接入。
- 真实电费结算、发票、资金划拨和收益分账。
- 跨省/跨国市场规则引擎。
- 自研 MQTT Broker、Kafka 或通用时序数据库。
- 基于深度学习的复杂气象预测；先用可解释基线模型。
- 无人值守地对真实设备执行高风险控制。

## 6. 产品闭环

1. 系统管理员注册站点和设备，绑定设备型号、安全边界与遥测点表。
2. 模拟器通过 MQTT 或 Netty 长连接上报遥测、心跳和指令回执。
3. 平台校验、标准化并写入 Kafka，实时计算设备状态、聚合功率和告警。
4. 运营员查看实时资源态势、数据新鲜度和异常。
5. 系统根据历史曲线生成次日负荷与光伏预测，并标明版本、置信信息和数据充分性。
6. 调度引擎结合分时电价和设备约束生成候选计划，展示成本、收益和约束告警。
7. 运营员审批计划后，平台将计划拆成设备指令并下发；设备返回接受、执行或失败回执。
8. 平台比较计划、实际功率和基线，计算达成率、节省金额、预测误差并写入审计链。

## 7. 成功指标

### MVP 验收指标

| 指标 | 目标 |
| --- | --- |
| 模拟设备规模 | 单机环境稳定维持 1,000 台、5 秒一次遥测，持续 2 小时 |
| 接入可用性 | 正常网络条件下有效遥测进入 Kafka 的成功率 ≥ 99.9% |
| 实时延迟 | 遥测接收至 WebSocket 可见的 P95 ≤ 3 秒 |
| 数据质量 | 重复数据不产生重复业务效果，乱序数据可识别且不回退设备当前状态 |
| 预测输出 | 每日输出次日 96 点预测；数据不足时拒绝伪造并返回原因 |
| 调度可执行性 | 所有计划点满足已知 SOC、容量、功率和可用性约束 |
| 指令追踪 | 每条指令具有创建、下发、接收、执行/失败的完整状态 |
| 审计可追溯 | 可按 `schedule_id` 还原输入版本、算法版本、审批人、指令和效果 |

### 业务效果指标

- 相对“无优化基线”的购电成本变化率。
- 负荷预测 WAPE/MAE、光伏预测 nMAE。
- 需求响应目标达成率和按时达成率。
- 储能等效循环次数与单位收益，避免以过度衰减换取表面收益。
- 告警平均确认时间与平均恢复时间。

## 8. 假设与约束

- MVP 是教学/作品集与可演示原型，不连接真实高压设备。
- 默认一个租户、多个组合、多个站点；数据模型保留多租户隔离字段。
- 所有时间在传输和存储中使用 UTC，界面按站点时区显示。
- 功率统一使用 kW，电量统一使用 kWh，价格统一使用 `CNY/kWh`。
- 15 分钟为预测和日前调度粒度；实时遥测为 5 秒粒度。
- 设备时钟可能漂移，服务端同时记录设备时间和接收时间。
- 预测模型只提供计划输入，不直接绕过审批控制真实设备。

## 9. 复杂度评估

- **等级：Level 3（复杂跨系统功能）**
- **原因：** 涉及多协议长连接、实时流、两类数据库、优化/预测服务、控制指令状态机、实时 UI 和跨系统审计。
- **升级条件：** 一旦连接真实设备、真实市场或资金结算，升级为 Level 4，并加入安全评审、现场联调、双人审批和回滚演练。

## 10. 待确认问题

以下问题不阻塞 MVP 启动，但应在 Phase 0 结束前确认：

1. 首个演示是否以工商业园区为主，还是以公共充电场站为主？默认工商业园区。
2. MQTT Broker 选 EMQX 还是 Mosquitto？默认本地 Mosquitto，压测/集群演示再切 EMQX。
3. 是否必须展示线性规划求解器？默认使用 OR-Tools 建模，并提供规则基线用于降级。
4. UI 是否要求移动端？默认桌面运营控制台，移动端仅自适应查看告警。
5. 是否需要多租户强隔离？MVP 做逻辑隔离，不承诺独立数据库或独立集群。
