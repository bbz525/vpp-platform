# 产品需求文档（PRD）

## 1. 发布范围

MVP 包含八个能力域：资源管理、设备接入、实时监控、告警中心、预测中心、调度中心、需求响应、审计与报表。

优先级定义：P0 为闭环阻塞项，P1 为首个完整演示应包含，P2 为后续增强。

## 2. 用户故事与功能需求

### 2.1 资源与设备管理

- **FR-RES-001 / P0**：管理员可创建组合、站点和设备，设备必须归属站点并具有唯一 `device_id`。
- **FR-RES-002 / P0**：设备型号定义遥测点表、单位、采样范围、可控能力和安全边界。
- **FR-RES-003 / P0**：设备凭证只显示一次明文，服务端仅保存可验证形式或外部密钥引用。
- **FR-RES-004 / P1**：设备可进入启用、停用、维护状态；维护设备不得参与自动调度。

验收标准：注册一台储能设备后，模拟器可使用其身份连接；停用后连接或上报被拒绝并留下审计事件。

### 2.2 设备接入与数据标准化

- **FR-IOT-001 / P0**：支持 MQTT 3.1.1/5.0 QoS 1 上报与 Netty TCP 自定义协议接入，两者映射为同一标准事件。
- **FR-IOT-002 / P0**：接收遥测、心跳、设备事件和指令回执，校验租户、设备、模式、字段类型、单位和时间戳。
- **FR-IOT-003 / P0**：以 `event_id` 幂等；保留 `device_time` 与 `ingested_at`；标记迟到、漂移和无效数据。
- **FR-IOT-004 / P0**：无效数据进入死信流，不污染当前状态和曲线，并可按原因查询。
- **FR-IOT-005 / P1**：支持断线重连和带上限的退避；服务端以心跳窗口判断在线状态。

验收标准：同一事件重复发送三次，只形成一个有效业务事件；旧事件可入历史，但不能覆盖更新的设备当前状态。

### 2.3 实时监控

- **FR-MON-001 / P0**：总览展示聚合功率、负荷、光伏、储能充放电、在线设备数和活动告警数。
- **FR-MON-002 / P0**：支持组合 → 站点 → 设备下钻，曲线显示数据时间和新鲜度。
- **FR-MON-003 / P0**：通过 WebSocket 推送聚合快照、设备状态变化、告警和计划执行状态。
- **FR-MON-004 / P1**：客户端断线重连后使用游标补取有限窗口；窗口外则请求 REST 快照重新同步。

验收标准：设备遥测进入后 3 秒内出现在总览；连接中断时界面明确显示“数据已过期”，不得继续伪装实时。

### 2.4 异常告警

- **FR-ALM-001 / P0**：支持设备离线、SOC 越界、功率越界、数据突变、遥测过期和指令超时规则。
- **FR-ALM-002 / P0**：告警状态为 OPEN、ACKNOWLEDGED、RECOVERED、CLOSED；恢复不能等同于已确认。
- **FR-ALM-003 / P0**：同一设备、规则和告警窗口内去重，保留首次、最近发生时间与次数。
- **FR-ALM-004 / P1**：运营员可确认、备注、关闭告警；所有操作进入审计日志。
- **FR-ALM-005 / P2**：支持通知策略、静默窗口和升级链。

### 2.5 预测中心

- **FR-FCT-001 / P0**：为站点和组合生成次日 96 点负荷、光伏预测，记录输入数据截止时间、模型版本和生成时间。
- **FR-FCT-002 / P0**：训练数据不足、缺失严重或模型不可用时返回 `INSUFFICIENT_DATA`/`FAILED`，不得填充为“真实预测”。
- **FR-FCT-003 / P1**：展示预测与实际对比、WAPE/MAE/nMAE，并可选择持久性基线。
- **FR-FCT-004 / P1**：允许运营员基于原因进行覆盖修正，原预测与修正值均保留。

默认充分性门槛：至少 28 天有效历史数据，最近 7 天数据完整率 ≥ 95%；阈值可配置并审计。

### 2.6 调度中心

- **FR-SCH-001 / P0**：根据预测、电价、设备可用性和约束生成次日 96 点候选计划。
- **FR-SCH-002 / P0**：目标函数至少包含购电成本、储能衰减成本和违约惩罚；结果必须给出输入与算法版本。
- **FR-SCH-003 / P0**：计划状态为 DRAFT、VALIDATED、APPROVED、ACTIVE、COMPLETED、CANCELLED、FAILED。
- **FR-SCH-004 / P0**：审批前再次校验设备状态和约束；审批后才可生成设备指令。
- **FR-SCH-005 / P0**：支持紧急停止；停止后不再创建新指令，并向活动设备发送安全目标。
- **FR-SCH-006 / P1**：支持日内滚动修正，但不能静默覆盖已审批计划，必须产生新版本。
- **FR-SCH-007 / P1**：展示优化计划与无优化基线的预估成本、峰值和储能循环差异。

### 2.7 指令执行

- **FR-CMD-001 / P0**：每条设备指令具有唯一 `command_id` 和幂等键，并关联计划、时段与设备。
- **FR-CMD-002 / P0**：状态为 CREATED、DISPATCHED、ACCEPTED、EXECUTING、SUCCEEDED、FAILED、TIMED_OUT、CANCELLED。
- **FR-CMD-003 / P0**：只对未确认的可重试阶段自动重发；设备必须按幂等键返回同一执行结果。
- **FR-CMD-004 / P0**：超时或失败时触发告警，计划效果统计不得把目标值当实际值。

### 2.8 需求响应

- **FR-DR-001 / P1**：运营员可创建削峰/填谷事件，指定时段、目标 kW、基线方法和响应组合。
- **FR-DR-002 / P1**：系统评估可调容量，不足时明确展示缺口，不允许以不可用设备凑数。
- **FR-DR-003 / P1**：目标分解为站点/设备计划，并复用调度审批与指令流程。
- **FR-DR-004 / P1**：事件结束后计算实际响应、目标达成率和数据质量等级。

### 2.9 审计与报表

- **FR-AUD-001 / P0**：记录登录主体、操作、对象、时间、请求关联 ID、变更前后摘要和结果。
- **FR-AUD-002 / P0**：算法决策记录预测、电价、约束、模型/算法版本、计划版本和求解结果摘要。
- **FR-AUD-003 / P0**：审计记录采用追加写；更正通过新事件表达，禁止原地静默修改。
- **FR-RPT-001 / P1**：按计划输出预测误差、执行偏差、成本变化、峰值变化和告警影响。

## 3. 核心业务规则

1. **功率符号：** 站点净功率大于 0 表示从电网购电；储能功率大于 0 表示放电、减小购电，负值表示充电。
2. **SOC 边界：** 任何自动计划都必须满足设备动态 `min_soc`、`max_soc`；默认保留 5% 安全裕度。
3. **能量平衡：** `SOC[t+1] = SOC[t] - discharge[t]*Δt/(capacity*η_discharge) - charge[t]*Δt*η_charge/capacity`，其中充电功率为负值，实现时应转换为非负充/放电变量避免符号歧义。
4. **禁止同时充放电：** 同一储能同一时段不能同时充电和放电。
5. **可用性优先：** 离线、停用、维护、活动严重告警设备不参与新自动计划。
6. **时间边界：** 电价、预测和计划时段均使用左闭右开区间；夏令时由站点时区转换层处理，存储仍为 UTC。
7. **数据真实性：** 缺测可插值用于模型特征，但必须保留质量标记；插值数据不得展示为原始实测。
8. **人工覆盖：** 人工修改计划必须填写原因、重新校验并生成新版本。
9. **安全失败：** 优化器、预测服务或 Kafka 不可用时，平台停止生成新自动计划；已下发控制由设备本地安全策略兜底。

## 4. 页面与状态矩阵

| 页面 | 加载/空状态 | 部分/过期状态 | 错误状态 | 成功状态 |
| --- | --- | --- | --- | --- |
| 实时总览 | 骨架屏；无设备时引导注册 | 显示最后更新时间、缺失站点和“非实时”标记 | 可重试 REST 快照，保留错误原因 | 实时指标与曲线持续更新 |
| 告警中心 | 无告警显示正常态 | 部分规则服务异常时标记覆盖不足 | 操作失败不乐观关闭告警 | 状态、责任人和时间线可见 |
| 预测中心 | 未生成/数据不足分开展示 | 缺失时段与质量评分可见 | 显示失败阶段、模型版本和重试 | 96 点曲线、指标和版本完整 |
| 调度中心 | 无计划时引导生成 | 约束冲突时给出不可行原因 | 求解失败不得产生可审批计划 | 候选、基线、约束和收益可比较 |
| 执行监控 | 未开始显示计划等待 | 部分设备失败显示完成比例 | 通信故障与设备拒绝分开展示 | 计划/实际/偏差及回执完整 |
| 审计日志 | 无记录时显示筛选提示 | 部分外部关联不可用时保留原 ID | 无权限与查询失败分开展示 | 按关联 ID 还原完整链路 |

## 5. 权限规则

- 所有业务查询必须带租户上下文；站点管理员还必须受站点范围约束。
- 计划生成与计划审批为不同权限；MVP 可由同一用户拥有，但审计中必须区分动作。
- 紧急停止权限独立授予，操作需要二次确认和原因。
- 审计员只读，不可修改业务对象或关闭告警。
- 设备身份只能发布自身遥测/回执并订阅自身指令主题。

## 6. 分析事件

| 事件 | 关键属性 | 用途 |
| --- | --- | --- |
| `dashboard_viewed` | tenant, portfolio, stale_state | 了解监控使用和数据质量 |
| `forecast_generated` | model_version, data_quality, duration, status | 评估预测可靠性 |
| `schedule_generated` | algorithm_version, feasible, cost_delta | 评估优化效果 |
| `schedule_approved` | schedule_version, approver, overrides | 审批追踪 |
| `command_terminal` | device_type, status, latency | 指令可靠性 |
| `alarm_transitioned` | rule, severity, from, to, actor | 运营效率 |
| `dr_event_completed` | target_kw, achieved_kw, quality | 响应效果 |

分析事件不能替代业务审计；审计记录具有更高完整性要求。

## 7. 非功能需求

- **性能：** 1,000 台设备、每 5 秒一次遥测；接入到 WebSocket P95 ≤ 3 秒。
- **可用性：** 本地演示环境核心链路支持单组件重启后恢复，不承诺生产级多活。
- **一致性：** 遥测采用至少一次投递和业务幂等；命令采用状态机与幂等回执，不宣称端到端 exactly-once。
- **安全：** 传输加密、设备身份鉴别、RBAC、租户隔离、凭证不落日志。
- **可观测性：** 指标、结构化日志、分布式追踪统一携带 `trace_id`、`event_id`、`schedule_id` 或 `command_id`。
- **可维护性：** 事件契约版本化，数据库迁移可重放，算法与模型版本可追溯。
- **恢复：** Kafka 消费者可从偏移重放；控制面数据库每日备份；ClickHouse 原始遥测按保留策略管理。

## 8. 发布阻塞条件

- P0 数据链路存在重复执行或租户串读。
- 计划可能违反 SOC/功率/容量硬约束。
- 指令缺少幂等键、终态或超时机制。
- 断流后 UI 仍显示为实时。
- 数据不足时预测或收益使用伪造值。
- 无法按计划 ID 追踪审批、指令和实际效果。

## 9. 开放问题

- 电价来源：静态导入、模拟市场流还是外部 API？MVP 采用版本化 CSV/管理端录入。
- 需求响应基线：历史同类日、最近 N 日还是用户上传？MVP 采用可配置的最近 5 个有效同类日均值。
- 真实天气特征来源与许可尚未选择；MVP 用模拟天气或用户导入数据，并清晰标注。
- 储能衰减成本参数由设备型号默认还是站点覆盖？建议型号默认、站点可覆盖且留审计。
